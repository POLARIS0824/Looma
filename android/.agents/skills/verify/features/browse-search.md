# Browse files and search notes

Users browse folders and recent notes, change list/grid and sorting, search titles, text and tags, and manage notes or folders through selection actions with Undo.

## Sub-features

- `browse-layout-sort`: Show as list/Show as grid, the `Sort by` sheet (`Last modified`, `Title A–Z`, `Title Z–A`) and pull-to-refresh keep the visible note set.
- `browse-folders`: create, open, go up, rename, move and delete a folder.
- `browse-selection`: long-press selects notes or one folder (never both); batch Move to…/Delete; single-note Rename and File info; snackbar Undo.
- `browse-relink`: renaming a note reports `Renamed, N backlink(s) updated` (or `Renamed`); renaming a folder shows `Folder renamed`; moving a note or folder also rewrites affected wiki links (and relative `![[…]]` image embeds when moving a note).
- `search-match`: title, body and tag queries list matching notes. Cards show the relative file path under the title, up to 3 cleaned/clipped matching lines (with keyword highlights) and up to 2 matching tag chips, reusing the home note card in list/grid mode; tapping a result opens the note in Edit mode.
- `search-empty-clear`: blank query hint, `No matching notes` (fades in after 300 ms), Clear search and Close search.
- `search-history`: submitted (Enter) or opened queries appear under `Recent searches` (tapping one fills and runs the query). Returning via Back from a result keeps search expanded without auto-focusing the input or opening the keyboard; a second Back collapses and clears search.
- `search-semantic`: the `Semantic search` switch inside expanded search persists across close/reopen within the session and shows 300 ms delayed status (`Unsupported`, `Checking`, `NeedsModel`, `NeedsIndex` with `Open semantic search settings`, `SearchFailed` with `Search again`); when `Ready`, blank hint becomes `Describe what you’re looking for` and tapping a passage result opens Read mode scrolled to that passage.
- `browse-stalled`: an unfinished rename/move journal shows a banner with Abandon. Source-only: no user path creates one.

## How to get to it (user POV)

- Connected Home root shows `Recent` (up to 10 newest notes), `Folders` (only when folders exist) and `Notes` (only when root-level notes exist). Inside a folder there are no section headers; a flexible `TopAppBar` shows `Go up one folder`, the current folder name as title, the parent path as subtitle (`Home` at depth 1, `Home / <parent>` at depth 2+), and `Search <vault>`, `Show as list`/`Show as grid`, and `Sort` actions (drawer menu, Settings avatar, and edge drawer swipe are hidden inside folders).
- On Home root, the search field is an EditText with description `Search` (its placeholder `Search <vault>` has no semantics), and `Show as list`/`Show as grid` and `Sort` sit inside that collapsed bar. Inside folders, tap the `Search <vault>` icon button.
- Long-press a note or folder. `New folder` and `New note` are menu actions behind the `Create new` toggle, hidden during selection.

## Driving it with control.py

Preconditions: doctor passes on connected Home root. Create two notes via [notes.md](notes.md); for relinking, one must link to the other.

- **Layout/sort.** `v tap --desc 'Show as list'`; `v assert --desc 'Show as grid'`; `v tap --desc 'Show as grid'`. `v tap --desc Sort`; `v assert --text 'Sort by'`; `v tap --text 'Title A–Z'` (U+2013 dash; plain `Title` matches nothing). Repeat `Title Z–A` and `Last modified`. Check the Notes order, not Recent, which is always newest first. Folders always sort by name.
- **Folder.** `v tap --desc 'Create new'`; `v tap --text 'New folder'`; `v assert --text 'Folder name'`; the dialog's field is then the only EditText: `v tap --class android.widget.EditText`; `v text Projects`; `v tap --text Create`; `v assert --text 'Folder created'` (its Undo deletes the folder). `v tap --text Projects`; `v assert --text 'This folder is empty'`; `v assert --text Home`; `v assert --text 'Home / Projects' --absent`; create nested `Sub` inside `Projects` and open `Sub` → `v assert --text 'Home / Projects'`; `v tap --desc 'Go up one folder'`; `v tap --desc 'Search <vault>'` opens search from inside the folder (`v tap --desc 'Close search'`); `v tap --desc 'Go up one folder'` returns to Root.
- **File info.** `v tap --text '<title>' --index 1 --long` (index 1 is the Notes card; 0 is Recent). `v tap --desc 'File info'`: rows `Location`, `Size`, `Modified`, `Words`, `Characters` and, with checkboxes, `Checklist` / `1 of 1 done`. Location uses `›` between folders. Close with `v tap --text OK`.
- **Rename and relink.** Long-press the linked target; `v tap --desc Rename`; `v assert --text 'File name'`; `v tap --class android.widget.EditText`; `v select-all`; `v text Renamed`; `v tap --text Save`. Expect `Renamed, 1 backlink(s) updated` (plain `Renamed` when no link changed). `v files <name>` shows `Renamed.md` and the referrer now holding `[[Renamed|…]]` (or `[[Renamed]]`). `v tap --text Undo` right away; `v assert --text Undone`; the file name and the link return.
- **Move.** Long-press a note; `v tap --desc 'Move to…'`; `v doctor --system`. DocumentsUI opens at the vault folder: `v tap --text Projects`; `v tap --text 'USE THIS FOLDER'`; `v tap --text ALLOW`. Expect `1 moved` + Undo, and the file under `Projects/`. A link that uses the bare file name keeps resolving and is not rewritten. Undo expires after about 10 s; a `v files` pull before tapping it can take longer.
- **Batch.** Long-press note A, then tap note B: the title is `2`, `File info` disappears and `Rename` is disabled. `v tap --desc Delete` has no confirmation: `2 moved to trash` + Undo → `Undone`.
- **Folder rename and delete.** Long-press `Projects` → `v tap --desc Rename`; `v assert --text 'Rename folder'`; `v tap --class android.widget.EditText`; `v select-all`; `v text Work`; `v tap --text Save` → `Folder renamed` + Undo (`Undone`). Empty folder delete: long-press empty folder → `v tap --desc Delete` → `v assert --text 'Delete “<name>”?'` and `v assert --text 'This folder has no indexed notes. Only empty folders are removed. Attachments and other files are kept.'`; `v tap --text Delete` → `Folder deleted` (Short, no Undo). Populated folder delete: `v tap --text Projects --long`; `v tap --desc Delete`; `v assert --text 'Delete “Projects”?'`; `v assert --text '1 note in this folder will move to the trash.'` and `v assert --text 'Attachments and other files are kept. Only empty folders are removed.'`; `v tap --text Delete` → `Folder deleted · 1 note moved to trash` + Undo (if non-note files remain, `Folder kept · …`). `v files <name>` shows `.looma/trash/` holding `originalPath=Projects/<name>.md`.
- **Search.** `v tap --class android.widget.EditText`; with no history expect `Search titles, text and tags`. `v text Verification` → result `Verification note`. `v tap --desc 'Clear search'`; `v text Persistence` (body); clear; `v text '#verify'` (tag). Press Enter: the query is recorded, the keyboard hides and the results stay; `v key KEYCODE_BACK` then returns Home and clears the query. Tapping a result opens the note and records the query; pressing Back returns to expanded search with the query intact and **without re-opening the keyboard**; pressing Back again (or `Close search`) collapses search and clears the query. Reopen the field: `Recent searches` lists `#verify` (tapping it fills and runs `#verify`). `v text nonexistent-verify-token` → `No matching notes`. `v tap --desc 'Clear search'`.
- **Semantic search toggle.** With search expanded, `v toggle 'Semantic search'` → if model/index missing, `v assert --text 'Download the model in Settings to use semantic search.'` (or `'Build an index for this vault in Settings to use semantic search.'`); `v tap --text 'Open semantic search settings'` → `v assert --text 'Find notes by meaning'`; `v tap --desc Back` leaves `Semantic search` on; `v toggle 'Semantic search'` back off, then `v tap --desc 'Close search'` → `v assert --desc 'Show as list'`. Full semantic passage search requires first downloading the 157 MiB EmbeddingGemma 2 model from Hugging Face and building the vault index in Settings.

## Gotchas

- Titles repeat across Recent, Notes, folder titles and the selection bar. Resolve `--index` from `v ui`.
- Do not press Enter until the results you want to inspect are on screen: submit records the query, hides the keyboard and keeps the results. A single Back then closes search; closing search clears the query.
- Dialog actions are text (`Create`, `Save`, `Delete`, `OK`); bar controls are descriptions.
- Snackbars with Undo use `SnackbarDuration.Long`; snackbars without Undo (e.g., empty `Folder deleted`, `Folder kept · No notes moved to trash`) use `SnackbarDuration.Short`. Assert messages before slow `v files` pulls.
- `Semantic search` switch state persists across closing/reopening search in the same session, though closing unloads the model from memory.
- A stalled relocation needs a broken `.looma/operations/op-<uuid>` journal. No harness command or user path creates one; report it as source-only.
