# Create, edit and read Markdown notes

Users create or open a note, edit its Markdown in one field, format it, switch to reading, follow wiki links, insert images and return without losing content. Files on disk are the durable source of truth.

## Sub-features

- `note-create-save`: New note creates `Untitled note.md` in the current folder and opens the editor with the title field focused and the default name selected; typed Markdown persists after leaving and relaunch.
- `note-title`: the filename is an editable title. With Show inline title on it sits above the body in Edit and Read; off it moves to a centered, smaller top-bar field. Typing a new name and committing (Done, focus loss, Edit→Read mode switch, or Back) renames the file and rewrites wiki links; blank names revert silently; a taken or blocked name shows a snackbar, reverts, and cancels a Back press. A new note names its file by typing into the focused title, so `Untitled note (1).md` no longer accumulates.
- `note-open`: Recent cards, Notes cards, folder cards and keyword search results open in Edit mode; semantic search results (`passage != null`) and large notes (`>= 262,144` chars) open in **Read** mode (semantic results scroll to the passage or show `This note changed since the search. Search again to find the passage.`).
- `note-read-edit`: the top-bar Read/Edit toggle preserves content and keeps the same paragraph at the top of the viewport in both directions. Read shows the inline title (the file name, display only and scrolling with the body), rendered Markdown (including GFM tables and pill inline code) and backlinks; tapping a checkbox rewrites `[ ]`/`[x]`.
- `note-rename`: editing the file name in the inline title (or in the top bar when Show inline title is off) in Edit mode renames the file in place (including case-only renames on case-insensitive storage) and retargets wiki links. Uppercase `.MD` suffixes open and normalize to `.md` on rename. Read never edits the name. A snackbar reports when backlinks were updated or failed.
- `note-format`: toolbar actions, Undo/Redo and the configured toolbar order change the Markdown.
- `note-links`: Link a note inserts a wiki link; Read resolves it live without leaving, opens the target, and the target lists `Backlinks · N`; a missing target shows a snackbar.
- `note-images`: Insert image picks a photo, writes `<first 16 hex of SHA-256>.<ext>` into the vault root (or `.obsidian/app.json`'s `attachmentFolderPath`, appending ` 1` on hash-prefix collision and reusing identical bytes) and inserts `![[…]]` (disambiguated path if shadowed or per `newLinkFormat`) in Local attachment mode, or uploads to S3 and inserts `![](url)` in Image bed mode. Moving a note rewrites relative `![[…]]` embeds. Read renders `![](…)` (`https://` only), `![[…]]`, sized `![[x.png|300]]`, and a `Retry` placeholder on failed loads.
- `note-math`: `$…$` and `$$…$$` render as formulas in Read.
- `note-conflict`: a save against bytes changed by another editor writes a conflict copy and shows a banner with Reload from disk and Overwrite; other save failures offer Retry save; leaving while a save fails or conflicts shows `Changes are not saved` (`Overwrite`/`Retry save` vs `Discard and go back`).

## How to get to it (user POV)

- Home → Create new → New note (in the current folder).
- Tap a card in Recent, Notes or folder contents, or a search result.
- A resolved wiki link or a backlink opens its target; Back returns to the prior note.

## Driving it with control.py

Preconditions: connected empty Home, English UI, doctor passes. Create fixtures through New note.

- **Create.** `v tap --desc 'Create new'`; `v tap --text 'New note'`. With Show inline title on (default) Edit has two `android.widget.EditText` nodes: index `0` is the single-line file name `Untitled note` (focused and selected on a new note), and index `1` is the Markdown body with placeholder `Start writing Markdown…`. Because `Untitled note` starts selected, press `v key KEYCODE_ENTER` (Done) to keep it and move focus reliably to the body (a tap on `EditText --index 1` right below can be swallowed by selection handles): `v text '# Verification note'`; `v key KEYCODE_ENTER`; `v text 'Persistence marker #verify'`; `v key KEYCODE_ENTER`; `v tap --desc Bold`; `v text formatted`; `v key KEYCODE_MOVE_END`; `v key KEYCODE_ENTER`. (`Bold` places the cursor inside `**|**`, so move to line end before Enter.)
- **Read/save.** `v tap --desc Read`. Read shows the inline title `Untitled note` (the file name) above the heading `Verification note`, and the title scrolls with the body; `formatted` renders bold. `v tap --desc Back`; `v files note-saved`. The file is `Untitled note.md` with `# Verification note`, `Persistence marker #verify` and `**formatted**`. The heading never renames the file.
- **Rename.** In Edit, `v tap --class android.widget.EditText --index 0`; `v select-all`; `v text 'Weekly notes'`; `v key KEYCODE_ENTER`. Done commits once, moves focus to the body and renames the file (`v files note-renamed`). Switching directly to `Read` (`v tap --desc Read`) or pressing Back also commits an edited focused title, including case-only renames (`weekly notes`). In Read the title is display only, so switch back to Edit to rename. When other notes linked to it, a snackbar reports the backlinks updated or failed.
- **Persistence/open entries.** `v relaunch`; `v ui`. Home shows each note twice (Recent and Notes), so pass `--index`. Repeat from the other card and from a keyword search result; record each entry separately.
- **Toolbar.** About ten of the twenty actions fit a 1080 px screen: Undo, Redo, Link a note, Insert image, Bold, Italic, Strikethrough, Highlight, Link, then Inline code, Heading 1–3, Bulleted list, Numbered list, Checklist, Quote, Code block, Table and Divider offscreen. Scroll the row with `v swipe left --desc Bold` (repeat with any visible action). `v tap --desc Checklist`; `v text Task`; `v tap --desc Read`. Read exposes an `android.widget.CheckBox`; `v tap --class android.widget.CheckBox` sets `checked=true`, and after Back the file holds `- [x] Task`. `Table` inserts `| | |\n| --- | --- |\n| | |` with the cursor in the first cell.
- **Links.** Create a second note: `Create new` → `New note`. Because `Untitled note.md` was renamed above, the new note defaults to `Untitled note` (not `Untitled note (1)`); type `Target note` into the focused title, `v key KEYCODE_ENTER`, `v text '# Target note'`, `v tap --desc Back`. In the first note (`Weekly notes.md`): `v tap --desc 'Link a note'`; `v assert --text 'Search notes'`; `v tap --text 'Target note'`. The inserted text is `[[Target note]]` (matching title and filename omit the alias; otherwise `[[<file>|<title>]]`). Type `[[Missing target]]` on another line, then immediately tap `Read`: the valid link resolves live without leaving and reopening the note. In Read the whole paragraph is one TextView; inspect `v ui` for its `--index` and tap spans with quoted `--at`: `v tap --class android.widget.TextView --index <idx> --at '0.4,0.75'` hits line 2. Expect the snackbar `No note named "Missing target"` (in PowerShell write `'No note named \"Missing target\"'`). Tapping line 1 opens the target in Edit; `v tap --desc Read` there shows `Backlinks · 1` and the referrer's title (`Verification note`).
- **Images.** Make a small disposable PNG on the host. `v fixture <file.png> --to pictures` pushes it to `/sdcard/Pictures/<owner>/` and runs the media scanner. In Edit, `v tap --desc 'Insert image'` (shows `Uploading image` while uploading); `v doctor --system`. The photo picker lists `Photo taken on …` items; their descriptions contain U+202F before AM/PM, so copy the exact `content-desc` from `v ui` JSON instead of typing it. After the pick: Read renders the image; `v files <name>` shows `<16 hex>.png` at the vault root, byte-identical to the fixture, and `![[<16 hex>.png]]` in the note.
- **Math.** `v text 'Energy $E=mc^2$ here'`; Read renders the formula inline. Home card previews show the raw `$…$` source.
- **Conflict.** Open a clean note. Write the "other editor" version on the host under the note's exact file name and push it with `v fixture '<file>' --to vault --replace`. Then type in the app: `v tap --class android.widget.EditText --index 1`; `v key KEYCODE_MOVE_END`; `v text ' app edit'`. Within about 3 s, after the 2 s debounce, `v assert --text 'Reload from disk'` and `v assert --text Overwrite`. The banner reads `The note changed on disk. Your changes were saved as “<name> (conflicted copy yyyy-MM-dd HHmmss).md”.` with curly quotes; read it from `v ui`. `v files <before>` shows that copy next to the note and the note holding the external bytes. `v tap --text Overwrite`: the banner closes, the note holds the app content, the conflict copy is gone and the external bytes are backed up under `.looma/conflicts/`.

## Gotchas

- With Show inline title on, Edit has two `EditText` nodes: index `0` is the inline file name and index `1` is the body. With Show inline title off, Edit **still has two `EditText` nodes** in reverse order because Compose `Scaffold` emits `content` before `topBar`: index `0` is the body and index `1` is the top-bar file name! Read has no `EditText` and shows the name as text. Draft recovery is gone.
- Saving: 2 s after the last edit, at most 15 s after the first edit of a burst, and on Back, pause and stop. Poll observable state and inspect disk; sleeps are not proof.
- Detection compares SHA-256 of the bytes, not mtime. An external change made while the app is in the background is taken silently on return if the note is clean; a conflict needs edits on top of an unseen external change.
- Predictive back runs only when the note is clean and requires no title commit; dirty/blocked notes open `NoteLeaveDialog` (`Changes are not saved`, `Saving failed. Going back now loses your changes`, `Overwrite`/`Retry save`, `Discard and go back`).
- Untouched new empty notes are discarded on leave unless Keep empty notes is on; renaming a new note keeps it even when empty and Keep empty notes is off.
- `Read` on a note opened from Read mode of another note: Back returns to that note, a second Back to Home.
- `Insert file` never appears in the toolbar. ADB ASCII input does not verify IME composition.
